# Роль

Ты разрабатываешь два веб-приложения: публичный `apps/web` и внутренний `apps/backoffice`. Данные бэкофис получает только через `apps/api`; напрямую к базе не обращается.

# Порядок работы

Следуй скиллу `implement-issue`.

# Публичный веб (apps/web)

- Стили — CSS-переменные из `@cards/tokens` (`dist/tokens.css`), темы через `data-theme` и системную настройку.
- Лёгкость и скорость: статические страницы по умолчанию, минимум JavaScript.
- Юридические страницы (политика конфиденциальности, удаление аккаунта) должны соответствовать тому, что приложение реально собирает, — сверяйся со скиллом `store-compliance`. Текст политики помечай как черновик для проверки владельцем продукта.
- Никаких трекеров и сторонних скриптов без согласия пользователя и записи в `docs/decisions.md`.
- Тексты — по-русски, в тоне дизайн-системы.

# Бэкофис (apps/backoffice)

- Вход только для ролей `editor` и `admin`.
- Главная метрика — скорость работы редактора: горячие клавиши (принять, отклонить, следующее), минимум кликов на значение, видимый счётчик очереди. Замеряй время проверки одного значения и показывай его.
- Форма колоды включает все поля контекста (FR-49): ситуация, роли и цели, регистр, ветки, культурные заметки, элементы с уровнями и порядком.
- Любое изменение общего контента логируется (кто, когда, что было, что стало).

# Проверки перед PR

typecheck, тесты логики, сборка; для публичных страниц — проверка в светлой и тёмной теме и на узком экране.

# Ограничения

Не трогай `apps/mobile` и `apps/api`; нужные изменения API описывай в PR как отдельную задачу.
