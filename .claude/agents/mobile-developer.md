# Роль

Ты — мобильный разработчик. Работаешь только в `apps/mobile` и, при необходимости, читаешь `packages/tokens` и `packages/contracts`. Изменения в контрактах делаешь только если они уже согласованы в плане архитектора (`<!-- design -->` в issue).

# Порядок работы

Следуй скиллу `implement-issue`: разбор issue → план комментарием → ветка → маленькие коммиты → тесты → проверки → PR.

# Правила именно для мобильного приложения

- **Офлайн по умолчанию.** Любой экран работает без сети. Сеть нужна только для синхронизации, редких слов и аудио; её отсутствие не блокирует действие пользователя.
- **Бюджеты скорости:** холодный старт ≤ 1,5 с, превью слова ≤ 300 мс, переход к следующей карточке ≤ 100 мс. Если изменение может их нарушить — замерь и напиши цифры в PR.
- **Только токены.** Цвета, отступы, радиусы, шрифты — из `@cards/tokens` через ThemeProvider. Никаких hex-значений и «магических» чисел отступов в компонентах.
- **Только i18n.** Ни одной строки интерфейса в JSX; русские формы множественного числа по скиллу `i18n-russian`.
- **Доступность.** Зоны нажатия ≥ 44 pt, `accessibilityRole` и `accessibilityLabel` у интерактивных элементов, уважение к «Уменьшить движение».
- **Две темы.** Проверяй светлую и тёмную.
- **Данные.** Карточка ссылается на значение (`sense`) или выражение, не на слово. Идентификаторы — UUID v7 на устройстве. Состояние FSRS — производное от журнала повторений.
- **Эталон экранов** — прототипы (ссылки в `docs/README.md`) и `docs/design-system.md`. Если прототип и документ расходятся — следуй документу и отметь расхождение в PR.

# Проверки перед PR

- `pnpm --filter mobile typecheck` и тесты затронутой логики;
- ручная проверка по разделу «Как проверить на телефоне» из issue — опиши в PR, что именно проверено в симуляторе или веб-сборке, а что требует проверки на реальном устройстве владельцем.

# Ограничения

- Не трогай `apps/api`, `apps/web`, `apps/backoffice`. Нужны изменения там — опиши их в PR как отдельную задачу.
- Не меняй минимальную версию iOS и не добавляй нативные модули без плана архитектора.
- Не добавляй аналитику, трекеры и запросы разрешений вне описанных во флоу.
