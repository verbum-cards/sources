# Конвейер словаря

## Этапы

1. **Исходный список** — `data/cefr_seed.csv` (headword, pos, cefr, source, license), собирается `data/build_seed.py` из CEFR-J (A1–B2) и Octanove (C1–C2).
2. **Разбор на значения через LLM** — формат `data/senses_sample.json`; промпт — `references/prompt.md`.
3. **Валидация** — схема, длины, уровни, теги (см. ниже).
4. **Выгрузка редактору** — CSV в порядке приоритета: слова колод и первой сессии → первые 3 000 по частотности → остальное.
5. **Импорт проверенного** — статусы `verified` / `rejected`, правки редактора.
6. **Сборка пакетов** — SQLite: стартовый (5 000 слов, только `verified`), основной (20 000); отчёт о размере.

## Правила данных

- Уровень из исходного списка — у самого простого значения слова; уровни остальных значений предлагает LLM, **не ниже** исходного.
- Перевод значения — 1–4 слова, самый употребительный русский эквивалент; синонимы через запятую, не больше трёх.
- Пример — **оригинальный**, естественный, 5–12 слов, лексика не сложнее уровня значения + 1; изучаемое слово в тексте, его позиция — `highlight`.
- Перевод примера — естественный русский, не калька.
- Теги — только из списка `references/tags.md`.
- Источник записи и статус сохраняются всегда. **Нельзя** копировать определения и примеры из словарей с закрытой лицензией (Cambridge, Oxford, Merriam-Webster и др.), в том числе «перефразировать» их.

## Валидация (автоматически, до выгрузки редактору)

- JSON соответствует схеме; нет пустых полей.
- Уровень значения ≥ уровня из исходного списка.
- Изучаемое слово (или его форма) присутствует в примере; `highlight` указывает на него.
- Длина примера 5–12 слов; перевод значения ≤ 4 слов.
- Теги из списка.
- Нет дубликатов значений у одной лексемы.

Всё, что не прошло валидацию, — в отдельный файл с причиной; не отправлять редактору.

## Выгрузка для редактора (CSV)

Колонки: `sense_id, lemma, pos, cefr, tags, ru, example, example_ru, source, status, editor_note`. Редактор меняет `ru`, `example`, `example_ru`, `cefr`, `tags`, `status` (`verified` / `rejected`) и пишет `editor_note`. Импорт сравнивает с исходником и логирует каждое изменение.

## Стоимость и отчёт

Каждый прогон пишет отчёт: число слов на входе, значений на выходе, ошибок валидации по типам, время, токены и стоимость LLM, стоимость на 1 000 слов. Ключ LLM — из окружения; модель указывается параметром.
