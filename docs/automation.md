# Фоновая разработка: как всё устроено и как включить

## Кто что делает

| Шаг | Кто | Воркфлоу |
|---|---|---|
| Создать issue по шаблону | Владелец | — |
| Разобрать: критерии, метки, вопросы, дробление | project-manager (скилл `triage-issue`) | `triage.yml` |
| План для архитектурных задач (`needs-design`) | architect | `design.yml` |
| **Взять в работу — метка `ready`** | **Владелец** | — |
| Ветка, код, тесты, PR | агент области (скилл `implement-issue`) | `implement.yml` |
| Типы и тесты | CI | `ci.yml` |
| Ревью PR | reviewer (скилл `review-pr`) | `review.yml` |
| Правки по замечаниям — комментарий с `@claude` в PR | разработчик | `claude.yml` |
| **Проверить на телефоне и влить** | **Владелец** | — |
| Закрыть задачи после merge | project-manager | `after-merge.yml` |
| Отчёт по понедельникам | project-manager (скилл `weekly-report`) | `weekly-report.yml` |
| Импорт бэклога недели в issues | project-manager | `import-backlog.yml` (запуск вручную) |

Агенты — в `.claude/agents/`, скиллы — в `.claude/skills/`, общие правила — в `CLAUDE.md`.

## Включение (один раз)

1. **Claude GitHub App.** В корне репозитория запустить `claude` и выполнить `/install-github-app` (нужен установленный и авторизованный `gh`). Установить приложение; от шага с воркфлоу можно отказаться — они уже лежат в `.github/workflows`.
2. **Токен подписки.** Локально выполнить `claude setup-token` и сохранить результат как секрет репозитория `CLAUDE_CODE_OAUTH_TOKEN` (Settings → Secrets and variables → Actions). Запуски будут расходовать лимиты вашей подписки.
3. **Токен GitHub для агентов — `CARDS_BOT_TOKEN`.** Создать fine-grained personal access token только для этого репозитория с правами: Contents — read/write, Issues — read/write, Pull requests — read/write, Metadata — read. Сохранить как секрет `CARDS_BOT_TOKEN`.
   Зачем: действия, сделанные стандартным `GITHUB_TOKEN`, не запускают другие воркфлоу, — тогда PR агента не получил бы ни CI, ни ревью. С этим токеном действия агентов будут видны в GitHub от вашего имени.
4. **Метки.** `bash scripts/setup-labels.sh`.
5. **Защита основной ветки** (Settings → Branches): изменения только через PR, обязательная проверка `CI / check`. Одобрение PR не требовать: PR агентов создаются от вашего имени, а свой PR одобрить в GitHub нельзя — контроль остаётся за вами через merge.
6. **Первые задачи.** Actions → Import backlog → Run workflow → неделя `01`. Затем указать сроки у созданных milestones «Неделя NN».

## Работа каждый день

1. Создать issue (шаблоны: функция, баг, контент) — хватит пары фраз.
2. Через несколько минут в issue появится разбор. Ответить на вопросы, если есть.
3. Поставить `ready` — агент сделает PR.
4. Прочитать ревью, при необходимости написать в PR `@claude исправь замечания ревью`.
5. Проверить на телефоне по инструкции из PR и влить.

Лучше держать в работе одновременно 1–2 задачи: в монорепозитории параллельные PR чаще конфликтуют.

## Расходы и ограничители

- Каждый запуск тратит лимиты подписки Claude и минуты GitHub Actions (у приватных репозиториев бесплатный объём ограничен).
- В каждом воркфлоу заданы тайм-аут и лимит ходов (`--max-turns`); повторные запуски по одному issue отменяют предыдущие.
- Модели: архитектор и ревью — Opus, разработка и разбор — Sonnet, отчёт — Haiku. Поменять — в `claude_args` воркфлоу и `model` в файлах агентов.

## Как остановить

- Одну задачу — снять `ready`.
- Всё — Actions → выбрать воркфлоу → Disable workflow.
- Полностью — удалить секрет `CLAUDE_CODE_OAUTH_TOKEN`.
